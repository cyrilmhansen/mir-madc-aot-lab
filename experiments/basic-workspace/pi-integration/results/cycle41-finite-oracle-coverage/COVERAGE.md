# Coverage

The campaign generated and ran 59 complete workflows through the three production gateway families. The frozen original priority sets (16 + 8) used two-target maintenance batches. After confirming that three targets were feasible, an amended independent-seed primary/secondary set (16 + 8) used three-target transactions. Exploratory smoke and control runs are retained separately. No attempt is overwritten.

`coverage-matrix.json` and `workflow-index.json` summarize counts; `differential-results.jsonl` contains the per-workflow oracle and both-engine observations with replay-prefix lists; `bridge-validation.jsonl` retains the bridge outcomes. Every workflow retains its generated mathematical specification, constructor/rename/v3 maintenance contracts, finite expected rows, complete constructive history, every revision snapshot, identity ledger, final replay comparison, and handoff/continuation manifests with trust anchors. Eight representative workflows retain full nested handoff packages and TypeScript/JSONL lifecycle evidence. Repeated successful gateway logs were compacted for the other 51 cases; exact seeds and contract generation allow regeneration. The one compact history reconstructed from its preserved typed specification and host contracts is labeled in `compact-evidence.json`.

Coverage includes seven semantic template families: raw `>=`, raw `<`, clamp, dependent predicate, sequential override, two callees, and dependency chain. Generated workflow counts span two and three functions; the current Cycle39 generator and Cycle19 configurations did not emit four-function cases for this campaign. Graphs cover independent functions, one-edge dependency, and two-edge fan-out / two-callee shapes. The generated four priority families vary names, handles, thresholds, edit targets and boundary corpora. The initial fixed controls cover clamp, dependent-predicate and chain families.

The amended 24-case confirmatory set varies the four formerly excluded families with three literal targets per atomic maintenance transaction. All are complete construction → authenticated creation handoff → rename → authenticated continuation → v3 maintenance → full replay workflows. The current generator contains no four-function priority template; therefore function-count four is untested here. Edits to unary-minus literal nodes remain unsupported. Finite tables validate only their declared input set.

Negative request counts are separated in `negative-controls.json`: repeated bridge schema and gateway controls are reported as events as well as distinct rejected fields/codes; malformed finite-table variants and trust-binding controls are reported separately. Repeated controls across workflows are not counted as independent authorization mechanisms.
