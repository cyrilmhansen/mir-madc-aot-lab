## Existing semantic path

`Workspace._prepare_transaction` builds a private candidate and applies it atomically. The typed projection represents an IF as an `IfBlock(condition, then_body, else_body, line)`, with no independent IF identity. Assignment statements retain stable IDs. `typed_expr.parse_request` validates typed expressions and resolves symbols; `expression_tokens` emits canonical tokens; `_index` rebuilds symbol/reference indexes. `SemanticTransactionKernel` owns preview IDs, candidate fingerprints, revision checks, revalidation and commit. The Pi extension communicates over the existing loopback JSONL bridge; it does not own policy or Workspace state.

The narrow gap was mutation of an existing IF condition. Reusing `edit_assignment_expression` would address the wrong entity; replacing the SCORE_CLASS body or editing rendered BASIC would weaken identity guarantees. The smallest operation therefore accepts a function ID, a typed control path, a direct result-assignment anchor, the exact old condition and a replacement condition. It resolves the IF in the projection, requires the anchor to be a unique direct branch assignment, parses both expressions through the existing typed parser, replaces only the canonical condition-token span, reindexes and verifies emitted references. The surrounding branch tokens and assignment identities remain unchanged. IF control markers still have no standalone IDs; the path and assignment anchor jointly identify the target.

## Mission boundary

The Cycle 28 gateway reconstructs the authentic Cycle 27 nine-operation stream through `Cycle20Gateway`, then uses its existing `SemanticTransactionKernel`. The bounded contract allows one exact SCORE_CLASS condition replacement and one additional semantic call edge. Existing function invariants and the full normalized candidate are checked before preview and again at commit. This remains a mission-specific adapter, not a general policy interpreter.

The production tool inventory is five tools: discover, inspect, preview conditional edit, commit preview and validate mission. The extension and JSONL bridge preflight exercises the same TypeScript handlers as Pi.

## Evidence limitations

- IF blocks do not have standalone portable identities. The final target is identified by revision-bound control path plus the stable `score_class.statement.category50` assignment anchor and an expected old condition.
- Replaced condition tokens receive new IDs. Other canonical tokens and all statement/function aliases are retained.
- The original live gateway did not journal every opaque symbol/statement ID. The separate replay identity table therefore explicitly compares two host-controlled Workspace instances; it does not claim to recover every transient ID from the live Pi process.
- A renderer focus enum typo and duplicate initial display event were found after the model run. The original emitted visual event file is retained as `real-agent-01/visual-events-original.jsonl`; the viewer input is a documented normalization with contiguous presentation sequence and the existing `verified_function_boundary` fallback. No model or semantic events were added.
- The run-time `MISSION.json` generated by the initial gateway version used a generic numeric-maintenance envelope. The final typed condition contract is stored separately as `contracts/mission.json` and `real-agent-01/verified-mission-contract.json`. The initial model run's Python gateway nevertheless enforced the same fixed function/path/old-condition/replacement tuple directly; the deterministic production preflight was repeated after moving those values into the explicit condition contract. This contract-file mismatch is retained as a harness limitation, not presented as a contract-driven model authorization result.
