# Generator grammar and budgets

The frozen campaign configuration is `campaign-config.json`. Seeds, value limits, function/history limits, selection approach, reducer attempt budget and timeout are registered before running generated cases.

## Generated forms

The generator emits only existing typed numeric constructors and existing portable operation families. Program templates cover clamps, less-than and greater-or-equal predicates, bound dependent predicates, ordered result assignments with later IF override, two distinct callees, and dependency chains. Each case stores its independent mathematical specification and exact portable operation stream.

All parameters and outputs are numeric. Numeric values are finite integers. Candidate constructors are checked through the canonical Workspace transaction before entering the valid corpus. Any failure at this stage is classified as a generator/fixture defect or a capability gap; it is not counted as a MIR discrepancy.

## Input selection

Each input corpus includes negative, zero and positive values, each threshold and its immediate neighbors, each clamp endpoint and its neighbors, and deterministic seeded interior values. The complete chosen list is recorded per case.

## Production selection

Production cases are selected deterministically by strata. They traverse the actual TypeScript schema handler, JSONL transport and Python production gateway. Any case that is only applied directly or replayed is counted only in the semantic tier.

## Reduction

The campaign reducer accepts a reducer predicate containing the original classification and executes every candidate in a fresh Workspace. It tries a fixed ordered set of simplifications, stops after 64 attempts, and accepts only candidates preserving both validity and the same classification. Injected mismatch reduction is reported separately from production findings.
